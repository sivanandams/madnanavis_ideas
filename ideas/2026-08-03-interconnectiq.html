SaaS Idea Log — 2026-08-03

InterconnectIQ

AI cross-checks solar/battery installation specs against each utility's interconnection rulebook and auto-fills the application — catching the technical rejections that stall installers' cash flow for weeks.

Target Customer

Small-to-mid residential and commercial solar/battery installers (5–75 employees) who don't have a dedicated, full-time interconnection coordinator on staff but still submit dozens of utility interconnection applications a month across multiple utility territories.

Pain Point

Before an installed solar or battery system can be turned on, the installer must file an interconnection application with the local utility, and every utility has its own technical rulebook — allowable breaker sizing (the "120% rule"), meter compatibility, rapid-shutdown and anti-islanding requirements, one-line diagram conventions, and net-metering tariff paperwork — all of which change periodically and differ from the neighboring utility's rules. Applications with even small technical mismatches get kicked back, adding 2–6 weeks of delay per project, which delays the installer's final payment and financing draw. Installers currently either hire a dedicated interconnection coordinator (a real job posting, $60K–$85K/yr) or have senior electricians burn hours manually re-checking every submission against scattered utility PDFs and portal instructions — an expensive, error-prone use of skilled labor that doesn't scale with growth.

MVP Workflow

  1. Installer uploads the system design export (PDF/CSV from Aurora Solar, OpenSolar, or SolarEdge Designer) along with the project address and target utility.
  2. Document AI extracts equipment specs: panel/inverter/battery models, system size, breaker and busbar ratings, meter type, and rapid-shutdown configuration.
  3. A maintained, per-utility rulebook database (curated from published interconnection standards for each covered utility) is checked against the extracted specs.
  4. Any mismatch — oversized breaker, unlisted rapid-shutdown device, wrong meter class, missing one-line diagram element — is flagged in plain English with the specific utility rule it violates, before submission.
  5. Once specs pass, the system auto-fills that utility's standard interconnection application form (or portal-ready data export) from the extracted data.
  6. The installer tracks each application's status and gets alerted on utility-side response deadlines and stale submissions needing follow-up.

Data & Integrations Needed

Document AI for design-export parsing (Aurora, OpenSolar, SolarEdge) Curated per-utility interconnection rulebook database PDF form-fill / portal data export DSIRE public database for state net-metering/rebate programs Status/deadline tracking & alerts

Pricing Model

Monthly subscription tiered by number of active utility territories covered (e.g., $299/mo for up to 3 utilities, $699/mo for up to 10), positioned against the $60K–$85K/yr cost of hiring a dedicated interconnection coordinator — an easy ROI case even at low adoption within a company.

First Version Scope

Cover the top 15–20 utilities across California, Texas, and Arizona (the highest-volume residential solar markets) with manually curated rulebooks and a single design-export format (Aurora Solar PDF) to start. Output is a filled, downloadable application packet — no direct portal submission or e-signature in v1. Distribute through solar installer trade associations, SEIA regional chapters, and installer-focused Facebook/Slack communities.

What Makes It Non-Obvious

Solar tech investment has overwhelmingly targeted the customer-facing layer — lead generation, financing, and design software (Aurora, OpenSolar, Sunlight, Mosaic) — because that's where the flashy demos and big contracts are. The interconnection paperwork layer looks boring and bureaucratic, so it's been left almost entirely to spreadsheets and tribal knowledge, even though it's the actual bottleneck that determines when an installer gets paid. It's also structurally defensible in a way a thin LLM wrapper isn't: the value comes from a maintained, jurisdiction-specific structured dataset of utility technical rules that must be tracked and updated as utilities change them, not from generic chat reasoning over unstructured text.
